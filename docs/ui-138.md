# Мониторинговый интерфейс Demerzel (#138)

Документ описывает текущий интерфейс и предлагает улучшения. Цель: понятно для junior-разработчика без подсказок и меньше ручной работы для senior. Предложения пока не реализованы; порядок внедрения в конце.

## Что есть сейчас

Код: `src/routes/+page.svelte` (около 1200 строк), компоненты в `src/lib/components/`.

**Шапка**
- Полоса с плакатом и версия сборки (`v0.55.27 · коммит`).
- Строка сводки: четыре иконки с числами (проекты, ошибки, порты, задачи). Подписей у чисел нет.
- Кнопки без текста: агенты, настройки приложения, проверка уведомлений, установка виджетов, панель окна, вид, тема. Подсказки только при наведении.

**Два режима вида** (переключатель в шапке, сохраняется в `localStorage`)
- «Колонки»: проекты и порты слева, задачи, процессы и агенты по центру, логи справа.
- «Вкладки»: четыре вкладки — «Проекты и порты», «Процессы», «Задачи», «Агенты». Логи открываются поверх.

**Карточка выбранного проекта** (`projectFocus`)
- Название, путь, кнопки «Запустить», «Стоп», «Редактор».
- Поле команды запуска.
- Блоки подряд: автозадачи, процессы, порты, задачи, агенты, потом логи. Вся карточка — одна длинная прокрутка.

**Настройки и инструменты разбросаны по четырём местам**
- Сканирование папок (`ScanSettingsDialog`).
- Агенты: приоритет и установка (`AgentsSettingsDialog`).
- Настройки приложения: экспорт и импорт (`AppSettingsDialog`).
- Проверка уведомлений — отдельная кнопка в шапке.

## Проблемы

1. **Два режима вида дублируют содержимое.** Любое изменение нужно делать дважды или проверять в обоих режимах. Для junior это путаница: непонятно, какой вид «правильный».
2. **Иконки без подписей.** Новичок не знает, что делает кнопка с роботом или с колонками, пока не наведёт курсор. Тултипы не работают на сенсорных экранах и не видны при скриншотах.
3. **Сводка — цифры без смысла.** «3, 1, 0, 6» непонятно без подписей. Нет ответа на вопрос «всё ли в порядке».
4. **Карточка проекта перегружена.** Шесть блоков подряд. Нужный для текущей задачи блок может оказаться за пределами экрана.
5. **Три места для настроек.** Пользователь не знает, где искать. Редкие настройки (голос, тихие часы, интервал опроса) лежат на виду.
6. **Названия не совпадают по смыслу.** «Процессы» — запущенные команды, «Автозадачи» — выбранные скрипты, «Задачи» — из GitHub и Notion. Это разные сущности с похожими словами.
7. **Логи — отдельный слой поверх.** Нет явной связи «ошибка → лог → что делать».

## Предложения

### Для junior: одно понятное место

- **Один режим по умолчанию: «Обзор».** Вместо колонок и вкладок — список проектов и у каждого строка со статусом: работает, упал, остановлен, есть ошибка. Режим «Колонки» остаётся как опция для тех, кто хочет всё сразу.
- **Подписи у кнопок в шапке.** Текст рядом с иконкой для первых двух недель использования, потом возможность скрыть.
- **Словарь на одной странице.** Короткий раздел «Что здесь что» в настройках: процесс, автозадача, порт, задача, агент, алерт. Одна фраза на каждое.
- **Статус простыми словами.** Вместо «Exited(1)» — «упал с кодом 1, 5 минут назад». Вместо «ok» у порта — «свободен» или «занят проектом X».

### Для senior: меньше ручной работы

- **Карточка проекта по задачам.** Сверху — то, что требует внимания (ошибки, упавшие автозадачи). Остальное — свёрнуто, раскрывается по клику. Одна кнопка «Подробнее» вместо шести блоков.
- **Один вход в настройки.** Все настройки в одном окне с вкладками «Основные» и «Дополнительно» (уже начато в #166). Туда же перенести сканирование папок и агентов.
- **Алерт → действие.** Если процесс упал, в карточке — кнопки «Перезапустить», «Посмотреть лог», «Отправить агенту». Сейчас это разбросано по интерфейсу.
- **Сводка с подписями.** «2 проекта работают · 1 ошибка · 3 порта заняты · 6 задач открыто». Ошибка — красным, и по клику — к проблемному проекту.

### Вкладка «Дополнительно» в настройках

Переносим редкие параметры: голос и фраза алерта, тихие часы, порог дедупа алертов, интервал опроса портов, лимиты автозадач (2 на проект, 4 всего). Обычный пользователь их не видит, senior открывает за секунду.

## Порядок внедрения

1. Подписи у кнопок шапки и понятные статусы (малые правки, без смены структуры).
2. Режим «Обзор» по умолчанию, колонки и вкладки — опции.
3. Карточка проекта: блоки «требует внимания» и «подробнее».
4. Перенос настроек в одно окно (продолжение #166).
5. Действия из алерта в карточке проекта.

## Открытые вопросы

- Оставлять ли режим «Колонки»? Предлагаю оставить как опцию, но не по умолчанию.
- Сколько времени показывать подписи у кнопок? Предлагаю два запуска или до первого нажатия «Скрыть подписи».
